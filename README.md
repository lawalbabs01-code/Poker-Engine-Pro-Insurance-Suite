## Security Architecture & Fair Play Guarantees
The top concern for any player is: "Is this site rigged?" We address this with a two-pronged approach.

**1. Cryptographic Shuffling**: We use a continuously seeded Random Number Generator (RNG) that shuffles the deck on the server side. The algorithm is a hybrid of the Fisher-Yates shuffle and a cryptographic hash function that maps the shuffle sequence to a unique game ID. This guarantees that no prediction is mathematically possible. We encourage operators to publish the seed hash before the game starts and reveal it after the hand for verification.

**2. Anti-Collusion Detection**: Our backend runs a "Temporal Graph Analysis" on player behaviors. If two players consistently play hands with each other without raising (a classic sign of soft-play or collusion), the system flags them for the operator's review. This is a passive monitoring system that requires constant server communication but operates reliably in the background without human intervention.

## Frequently Asked Questions
*Q: Can I modify the source code to add a custom game mode?*
A: Absolutely. The codebase is modular; adding a new game mode requires creating a new "Rules Engine" class in `/engine/games/` and integrating it into the `/includes/` router.

*Q: Is the source code encrypted?*
A: The code is encoded using Zend Guard/IonCube to protect the core logic, but the frontend assets (HTML, CSS, JS) are fully viewable and editable. We provide an un-encoded version of the "Insurance Calculator" for verification of fairness.

*Q: What happens if my server crashes?*
A: The engine uses a "Replay Protocol." If the server restarts, all players who were mid-hand are returned to the lobby with a "Session Restore" token, and the incomplete hand is voided, returning bets to the players' stacks.
